# mysql-ha: a MySQL lab for `collect-collmysql.sh`

Three long-lived containers that the collector runs **inside**, the way the
field runs it on the database host (it reads `/proc`, the datadir, `auto.cnf`,
the binary logs, the error log). Built for the XLSMART/smartfren case
(`analysismain/cases/2026-09-17-xlsmart-mysql-io/`), whose first field run
ended in `mysql connection: access denied`.

| container | image | what it is | host port |
|---|---|---|---|
| `jjsong-ggt-mysql-primary` | `jjsong-ggt-mysql-ubuntu80:1` | Ubuntu 22.04 `mysql-server-8.0` package (8.0.4x), binlog + GTID, `server_id=1` | 127.0.0.1:33081 |
| `jjsong-ggt-mysql-replica` | same | GTID async replica of the primary (`SOURCE_AUTO_POSITION`), `super_read_only`, `server_id=2` | 127.0.0.1:33082 |
| `jjsong-ggt-mysql-57` | `jjsong-ggt-mysql-57:1` (`mysql:5.7.32` + procps, sysstat) | 5.7 single node, binlog + GTID | 127.0.0.1:33057 |

The Ubuntu image is the package the customer uses (requester, 2026-09-24):
`root@localhost` is `auth_socket`, config in `/etc/mysql`, error log
`/var/log/mysql/error.log`, a user `op` with NOPASSWD sudo. The 5.7 root has a
password (so a no-option-file run there is refused, like XLSMART's first run).
All nodes: `performance_schema` on, `innodb_buffer_pool_size=64M`,
`max_connections=40`, `--memory 768m`, `--cap-add SYS_PTRACE` (a host root has
it; docker's root does not), `--restart unless-stopped`.

Seed (`seed.sql`, `load.sql.sh`): schemas `account` and `notihub` with
`shedlock` (ShedLock's table), `MeteringDaily`/`MeteringHourly`, `AuditLog`,
`monitor_event`, `ReserveEvent`, `DeniedIPAddress`, `ApmRegion`, and 3000
scheduler-like write rounds, so section I has row events to attribute. Table
shapes other than `shedlock` are made up.

Accounts (all `'%'`):

| `GGT_ACCOUNT` | user | grants | stands for |
|---|---|---|---|
| `app` (default) | `whatap` | ALL on `account.*`, `notihub.*` | the application account of runbook section 6 (the real one's grants are not known) |
| `mon` | `ggtmon` | SELECT, PROCESS, REPLICATION CLIENT, SHOW VIEW on `*.*` | a monitoring account |
| `wrong` | `whatap` | wrong password | the XLSMART `access denied` shape |
| `none` | - | no option file: client defaults, root over the socket | runbook section 3 (first try) |

Credentials are generated by `up.sh` into
`~/.claude/lab-secrets/jjsong-ggt-mysql.env` (mode 600; `GGT_MYSQL_SECRETS`
overrides the path). They are never in this directory.

## Run

Every script honours `DOCKER_HOST`. The lab lives on the docker VM, not on the
analysis machine:

```sh
export DOCKER_HOST=ssh://ggt-docker
./up.sh                      # idempotent: reuse running, start stopped, create absent (builds images if missing)
./run-collector.sh jjsong-ggt-mysql-primary --file --binlog
GGT_ACCOUNT=mon   ./run-collector.sh jjsong-ggt-mysql-replica --file --binlog
GGT_ACCOUNT=wrong ./run-collector.sh jjsong-ggt-mysql-57 --file
COLLECTOR=/path/to/other/collect-collmysql.sh ./run-collector.sh jjsong-ggt-mysql-57 --stdout
./open-trx.sh jjsong-ggt-mysql-primary 300   # hold a transaction open 300 s (sections E, H)
./load.sh jjsong-ggt-mysql-primary 300       # more write rounds (a fresh binlog tail)
./down.sh                    # escape hatch only: stop; --rm removes containers and data
```

`run-collector.sh` copies the collector into `~/ggt-run/` of `op` (Ubuntu) or
root (5.7), writes `~/.my.cnf` mode 600 from stdin (no password on any
command line), runs `sudo ./collect-collmysql.sh ARGS --defaults-file=$HOME/.my.cnf`
(runbook section 6; on 5.7, root without sudo), removes the option file, and
copies the report to `GGT_OUT` (default `./ggt-out`). It prints the runbook
section 4 lines.

## What a run showed (0.10.5, 2026-09-27)

| node | `app` | `mon` | `none` | `wrong` |
|---|---|---|---|---|
| primary | login ok; INCOMPLETE (I: SHOW BINARY LOGS denied) | COMPLETE | COMPLETE (auth_socket) | access denied |
| replica | login ok; INCOMPLETE (same) | COMPLETE | - | - |
| 5.7 | login ok; INCOMPLETE (same) | COMPLETE | access denied | access denied |

With `app`, schema-only grants leave `n/a (access denied)` on B (replica,
master, group replication), C `SHOW BINARY LOGS`, E `SHOW ENGINE INNODB STATUS`
and all of G (`performance_schema`). With `mon`, only `SHOW REPLICAS` /
`SHOW SLAVE HOSTS` stay denied (they need REPLICATION SLAVE), and on 5.7 the
8.0-only syntax (`SHOW REPLICA STATUS`, `SHOW REPLICAS`) answers 1064 as designed.

On 8.0 section F's "tables whose name contains lock/metering/event/audit"
lists only `shedlock` and `monitor_event`: `information_schema.tables.table_name`
compares case-sensitively there, so `MeteringDaily`, `AuditLog`,
`ReserveEvent` do not match `LIKE '%meter%'`. 5.7 lists all seven.

Not covered: group replication (XLSMART's HA), a remote `db-lb` TCP login,
MariaDB, an 8.4 package.
